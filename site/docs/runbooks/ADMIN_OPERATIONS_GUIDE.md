# Credentialless Admin Operations Guide

## Purpose

`/admin` is an owner-facing launch map for the existing GitHub repository. It does not create a repository, store credentials, call provider APIs, or mutate GitHub from the browser.

## One-time setup

1. Open `/admin` on the deployed site.
2. Paste the existing repository as `owner/repository`.
3. Select **Save links**.
4. The repository value stays in that browser's local storage only.

An optional deployment default can be set with `VITE_GITHUB_REPOSITORY`. This value is a public repository address, not a secret.

## Operating sequence

1. Open and run the Kokoro audition workflow.
2. Edit the narrator selection and scorecard in GitHub.
3. Edit each final script, plaintext narration, and human-pass checklist.
4. Run **Approve Human Pass** once per video. GitHub validates the checklist, records the script SHA-256, updates the checklist receipt, commits, and pushes.
5. Run the twenty-video render workflow after approvals reach 20/20.
6. Download and human-review the WAV and MP4 artifacts.
7. Follow the YouTube runbook for local OAuth, dry-run receipts, and provider publication.
8. Confirm public playback before syncing real IDs into the site.

## Status truth

The `/admin` readiness counters come from `content/admin-status.json`, regenerated by `npm run generate`. They describe the deployed snapshot, not live GitHub Actions or YouTube state. Rebuild and redeploy the site after repository state changes when updated counters are needed.

## Security boundary

- GitHub handles authentication after a link is opened.
- OAuth and refresh-token files remain outside the repository.
- The browser stores only the non-secret repository name.
- No client-side button claims to publish, render, approve, or upload anything.
